# AI_CONTEXT.md — контекст проекта для ИИ-ассистента

Вставь этот файл целиком в начало диалога с любой моделью (Claude,
ChatGPT, Cursor, Copilot Chat и т.п.) перед тем, как просить её
что-то поменять в проекте. Здесь описано, что это за проект, как он
устроен, где что лежит, какие есть соглашения и на что нельзя ломать
поведение при правках.

## Что это за проект

Веб-тренажёр SQL-запросов на Flask. Пользователь видит карточку с
текстовым заданием, единую ER-схему базы данных (общую для всех
заданий) и терминал, куда вводит SQL-запрос. Запрос НЕ выполняется
по-настоящему (нет подключения к реальной БД) — он сравнивается
текстово с эталонным запросом, заданным в карточке.

Стек: Python 3, Flask, Jinja2-шаблоны, ванильный JS (без сборщиков,
без npm, без фреймворков на фронте), YAML для хранения карточек,
обычный `.sql`-файл для схемы БД. Данные хранятся в файлах на диске,
базы данных (в смысле СУБД) в проекте нет вообще.

## Ключевые концепции

### 1. Схема БД — ОДНА на весь проект, не на карточку

Раньше (в старой версии) у каждой карточки была своя `schema:` в
YAML. Сейчас это НЕ ТАК. Схема ровно одна, лежит в
`schema/database.sql` как обычный текст с `CREATE TABLE ...`
(включая `FOREIGN KEY (col) REFERENCES table(col)` для связей между
таблицами). Она:

1. читается один раз при старте приложения в `app.py`:
   ```python
   SCHEMA_TABLES = parse_schema(load_shared_schema())
   SCHEMA_LINKS = flatten_links(SCHEMA_TABLES)
   ```
2. НЕ перечитывается на каждый запрос — это модульные константы. Если
   меняешь `schema/database.sql` во время работы `flask run` без
   `--debug`/автоперезагрузки, нужно перезапустить процесс, иначе
   изменения не подхватятся.
3. Карточки (`cards/*.yaml`) больше не содержат поле `schema` — не
   добавляй его обратно, если не попросили явно вернуть старое
   поведение.

Текущая схема — учебная БД "авиаперелёты":
`Company`, `Trip` (у Trip есть `company` → FK на `Company.id`),
`Passenger`, `Pass_in_trip` (FK на `Trip.id` и `Passenger.id`).

### 2. Формат карточки задания (`cards/NNN_slug.yaml`)

```yaml
id: 3
title: "Рейсы и авиакомпании"
task: |
  Для каждого рейса выведи его id и название авиакомпании,
  которая его выполняет (объедини Trip и Company).
answer: "SELECT Trip.id, Company.name FROM Trip JOIN Company ON Trip.company = Company.id;"
```

Поля: `id` (int, уникальный, генерируется автоматически при создании
через `core/card_loader.py::_next_id()`), `title` (для списка и
заголовка карточки), `task` (текст задания, многострочный через `|`),
`answer` (эталонный SQL-запрос — единственная строка, используется
только для сверки, пользователю не показывается, пока он сам не
нажмёт «Показать эталонный запрос»).

Имя файла: `{id:03d}_{slugify(title)}.yaml`, генерируется
автоматически в `save_new_card()`. Руками добавлять файлы тоже можно
— главное, чтобы `id` был уникален, имя файла на логику не влияет
(`card_loader` матчит по полю `id` внутри YAML, а не по имени файла).

### 3. Как сверяется запрос — `core/checker.py`

`normalize_sql(query)`:
- `strip()`, убирает завершающую `;`
- `lower()` — НО не трогает регистр внутри одинарных кавычек (строковые
  литералы остаются как есть, значит `'Moscow'` ≠ `'moscow'`)
- схлопывает любые пробелы/переносы строк в один пробел
- убирает пробелы вокруг `,` `(` `)`
- НЕ нормализует пробелы вокруг `=`, `<`, `>` и других операторов —
  это осознанное ограничение из исходного ТЗ, не баг

`compare_query(user_input, answer)` возвращает `(correct: bool,
message: str)`. При несовпадении ищет первую отличающуюся позицию в
нормализованных строках и формирует сообщение с фрагментом до/после
расхождения (см. `_first_diff_message`).

Если меняешь алгоритм сравнения — не убирай регистронезависимость вне
строковых литералов и сохраняющуюся чувствительность внутри них, это
явное требование исходного ТЗ.

### 4. Парсинг схемы для ER-диаграммы — `core/schema_parser.py`

`parse_schema(schema_text) -> list[dict]` — вход: сырой текст с одним
или несколькими `CREATE TABLE ... (...);`. Работает через посимвольный
подсчёт глубины скобок (`_find_matching_paren`, `_split_top_level`), а
не через одну хрупкую regex на весь блок — так корректно
обрабатываются вложенные скобки внутри `FOREIGN KEY (col) REFERENCES
table(col)` и типы вида `VARCHAR(50)`.

Возвращает список таблиц:
```python
{"name": "Trip", "columns": [{"name": "id", "type": "INTEGER", "pk": True}, ...],
 "foreign_keys": [{"column": "company", "ref_table": "Company", "ref_column": "id"}]}
```

`flatten_links(tables)` превращает `foreign_keys` каждой таблицы в
плоский список для отрисовки линий: `{"from_table", "from_col",
"to_table", "to_col"}`.

Поддерживаются: колонки с `PRIMARY KEY` (в конце определения
колонки), табличные `FOREIGN KEY (col) REFERENCES table(col)` и
инлайновые `col TYPE REFERENCES table(col)`. НЕ обрабатываются:
составные первичные ключи через отдельный `PRIMARY KEY (a, b)` (строка
просто игнорируется, ни одна колонка не получит `pk: True`) и
`ON DELETE/UPDATE ...` после `REFERENCES` (тогда `_INLINE_REF_RE` всё
равно матчит `table(col)`, но не проверяли лишние токены после — при
необходимости протестировать отдельно).

### 5. Верстка тренажёра — `templates/index.html`

Двухколоночный layout `.layout`: слева `.side-panel` (блок задания +
кнопка показа ответа + мини-список всех заданий с навигацией по
карточкам), справа `.main-panel` (текстовый редактор запроса сверху,
вкладки «Результат» / «Схема» снизу).

Вкладка «Схема» рендерит `schema_tables` (из Flask-контекста) как
карточки таблиц (`.schema-table`), а связи (`schema_links`, embedded
как JSON в `<script type="application/json" id="schemaLinksData">`)
дорисовываются JS-ом поверх SVG (`static/app.js::drawSchemaDiagram`) —
линии считаются по `getBoundingClientRect()` DOM-элементов колонок
(`id="schema-col-{table}-{column}"`), поэтому таблицы/колонки должны
сохранять этот паттерн id, если трогаешь верстку.

Важно: диаграмма перерисовывается только когда вкладка «Схема»
активна (`requestAnimationFrame(drawSchemaDiagram)` в
`activateTab()`) и по `resize`, если эта вкладка открыта — потому что
у скрытых (`hidden`) элементов нулевые размеры, посчитать линии для
них нельзя.

### 6. Дизайн-токены — `static/style.css`, секция `:root`

Тёмная тема: `--bg #0e1116`, `--panel #171b24`, `--accent #e0a458`
(тёплый янтарный), `--ok`/`--err` для результатов проверки. Шрифты:
`--mono` = JetBrains Mono (код, терминал, схема), `--serif` = Source
Serif 4 (заголовки и текст задания — сознательный контраст с
моноширинным телом, не убирать). Все новые компоненты должны
использовать эти переменные, а не хардкодить цвета.

### 7. Роуты (`app.py`)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | случайная карточка |
| GET | `/card/<id:int>` | конкретная карточка |
| POST | `/check` | JSON `{card_id, query}` → `{correct, message}` |
| GET | `/cards` | список карточек |
| GET/POST | `/cards/new` | создание карточки (без поля schema!) |
| GET/POST | `/cards/<id:int>/edit` | редактирование карточки |
| POST | `/cards/<id:int>/delete` | удаление карточки |

`_render_trainer(card, cards)` — общий хелпер, всегда прокидывает
`schema_tables`/`schema_links` из модульных констант, даже если
`card is None` (пустое состояние — просто в шаблоне блок со схемой не
рендерится, т.к. обёрнут в `{% if card %}`).

## Правила при внесении изменений

1. Схема БД одна на все задания — не возвращай `schema:` в карточки,
   если явно не попросили откатить это решение.
2. `core/*.py` не импортирует Flask и ничего не знает про HTTP —
   держи бизнес-логику отделённой от `app.py`, если добавляешь новые
   функции.
3. Все цвета/шрифты — через CSS-переменные из `:root`, не хардкодь.
4. JS — один файл `static/app.js`, один IIFE, без внешних библиотек и
   без ES-модулей (проект не использует сборщик).
5. Если меняешь формат карточки или схемы — обнови и `README.md`, и
   этот файл, и существующие карточки/схему под новый формат, чтобы
   всё осталось консистентным.
6. Перед тем как что-то менять в `core/checker.py`, `core/schema_parser.py`
   или файлах в `cards/`/`schema/` — прогони sanity-check через Flask
   test client (`app.test_client()`), а не только глазами по коду:
   реальные баги в этом проекте чаще всего в regex/парсинге границ.
