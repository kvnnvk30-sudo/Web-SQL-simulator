# AI_CONTEXT_DOCKER.md — как устроена контейнеризация sql_flashcards

Файл для ИИ-ассистента. Читай его вместе с `AI_CONTEXT.md`, прежде чем
менять что-либо, связанное с Docker, окружением или запуском. Здесь
описано, что сделано, почему именно так и какие инварианты нельзя
ломать.

## 1. Что есть

Четыре файла в корне проекта:

| Файл | Назначение |
|------|------------|
| `Dockerfile` | образ Flask-приложения на `python:3.12-slim` |
| `docker-compose.yml` | два сервиса: `db` (`postgres:16`) и `app` (Flask) |
| `.dockerignore` | исключает из контекста сборки `.env`, `venv/`, `__pycache__/`, `.git/`, IDE-файлы, логи и сами docker-файлы |
| `.env.example` | шаблон переменных; используется и для локального запуска, и compose'ом |

Код приложения (`app.py`, `core/*`) для Docker **не менялся**. Всё
работает за счёт переменных окружения и способа запуска.

## 2. Как это работает при `docker compose up --build`

1. Собирается образ `app`: копируется `requirements.txt`, ставятся
   зависимости, затем копируется весь проект (включая `cards/*.yaml`,
   `schema/database.sql`, `templates/`, `static/`).
2. Стартует `db`. Официальный образ Postgres при первом запуске создаёт
   базу `POSTGRES_DB`, пользователя `POSTGRES_USER` с паролем
   `POSTGRES_PASSWORD`.
3. Healthcheck `db` (`pg_isready`) проверяется каждые 3 секунды.
4. Только когда `db` стал `healthy`, стартует `app`
   (`depends_on: condition: service_healthy`).
5. Контейнер `app` выполняет
   `flask --app app run --host 0.0.0.0 --port 5000`. При импорте
   `app.py` вызывается `init_db()`: DROP всех таблиц, затем полный
   `schema/database.sql` (CREATE TABLE + INSERT). Потом Flask слушает
   порт 5000, наружу он пробрасывается как `${APP_PORT:-5000}`.

## 3. Ключевые решения и почему они такие

### Запуск через `flask run`, а не `python app.py`
В `app.py` внизу `app.run(debug=True)`. Он слушает только `127.0.0.1`
и из контейнера недоступен. Вместо правки `app.py` приложение
запускается через flask CLI с `--host 0.0.0.0`. Блок
`if __name__ == "__main__"` при этом не выполняется, а `init_db()`
вызывается при импорте модуля, так что порядок инициализации прежний.
Побочный эффект: debug и авто-перезагрузчик выключены (это правильно
для контейнера).

### Порядок старта критичен
`init_db()` выполняется при импорте `app.py`, до первого запроса, и
сразу открывает соединение. Если Postgres не готов, процесс упадёт с
`OperationalError`. Поэтому обязательны и healthcheck в `db`, и
`depends_on: condition: service_healthy` в `app`. **Не заменяй это на
простой `depends_on` без condition и не убирай healthcheck.**

### Хост БД задаётся в compose, а не в `.env`
`core/db.py` читает `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`,
`DB_PASSWORD` через `os.getenv` (дефолт хоста — `localhost`). В compose
для `app` эти переменные заданы в `environment:`, причём
`DB_HOST: db` (имя сервиса) и `DB_PORT: 5432` зашиты в
`docker-compose.yml`. Имя базы, пользователь и пароль подставляются из
`.env` рядом с compose-файлом (или дефолтов `sql_trainer`/`postgres`/
`postgres`) и идут и в `db`, и в `app` из одного источника, поэтому
рассинхронизироваться не могут.

`load_dotenv()` в `db.py` не перезаписывает уже заданные переменные
окружения, а `.env` в образ не попадает (`.dockerignore`), так что
значение `DB_HOST=localhost` из `.env`, нужное для локального запуска,
контейнеру не мешает.

### Нет volume у Postgres
Схема и данные пересоздаются при каждом старте приложения. Хранить в
Postgres нечего, поэтому volume не нужен. Пользователь явно подтвердил:
нужна только рабочая структура данных. Если в будущем появятся
пользовательские данные в БД (прогресс, история), тогда добавлять
volume `pgdata:/var/lib/postgresql/data` **и** менять `init_db()` — не
дропать таблицы. Сейчас так делать не нужно.

### Карточки запечены в образ
Стандартный набор (10 карточек `cards/*.yaml`) копируется в образ, так
как требование пользователя — чтобы минимум 10 карточек шли «из
коробки». Отдельного volume/bind mount под `cards/` нет. Следствие:
карточки, созданные через UI (`/cards/new`) или изменённые/удалённые,
хранятся только в файловой системе контейнера и пропадают при
пересоздании контейнера. Это принято осознанно. Чтобы добавить карточку
в стандартный набор, положи YAML в `cards/` и пересобери образ.
Если позже потребуется сохранять правки из UI, вариант — bind mount
`./cards:/app/cards` (тогда набор на хосте становится источником
истины; учти права на запись).

`core/card_loader.py` строит путь к `cards/` от `__file__`, поэтому в
`/app/cards` он работает без изменений.

### Настройки цветов подсветки — не в контейнере
Цвета подсветки SQL хранятся в `localStorage` браузера, а не на
сервере: контейнеры, Postgres и `cards/` к ним отношения не имеют,
и `docker compose down` их не стирает (в отличие от карточек,
созданных через UI). Серверных роутов и volume под это нет и не
нужно. Стандартная палитра — `--hl-*` в `static/style.css`; она
запечена в образ, поэтому её правка требует пересборки.

### Python 3.12 и psycopg2-binary
В `requirements.txt` стоит `psycopg2-binary>=2.9.9` (без жёсткого
пина). Раньше уже была проблема несовместимости версии
`psycopg2-binary` и версии Python (сборка из исходников падала). На
`python:3.12-slim` ставится готовый wheel, `libpq-dev` и компилятор не
нужны. Если поднимать базовый образ (например, до 3.13), проверь, что
для этой версии Python есть wheel у выбранной версии `psycopg2-binary`;
не добавляй `libpq-dev`/`gcc` «на всякий случай».

### Порты
- `app`: контейнерный порт 5000, на хосте `${APP_PORT:-5000}`
  (переменная нужна, например, из-за AirPlay на macOS, который
  занимает 5000).
- `db`: порт 5432 **не публикуется** наружу, чтобы не конфликтовать с
  локальным Postgres. Приложение ходит к нему по внутренней сети
  compose. Для отладки через `psql` можно временно добавить
  `ports: ["5433:5432"]`, но не коммить это по умолчанию.

## 4. Инварианты, которые нельзя ломать

- Не хардкодь `localhost` в коде приложения: все параметры подключения
  идут только через `core/db.py` (`get_connection()`), им же
  пользуются `checker.py` и `db_init.py`.
- Не убирай healthcheck и `condition: service_healthy`.
- Не клади `.env` в образ (он в `.dockerignore`) и не коммить секреты в
  compose-файл: значения по умолчанию (`postgres`/`postgres`) годятся
  только для учебного стенда.
- Не меняй `app.py`/`core/*` ради Docker без явной необходимости;
  сначала ищи решение через окружение и команду запуска.
- `cards/` не добавляй в `.dockerignore`, иначе образ окажется без
  стандартных карточек.
- Не публикуй порт Postgres по умолчанию.

## 5. Типовые изменения

| Что нужно | Куда смотреть |
|-----------|---------------|
| Изменить схему/данные БД | `schema/database.sql` + `docker compose up --build`. Если добавляешь или переименовываешь таблицу, обнови `_DROP_ORDER` в `core/db_init.py` |
| Добавить стандартную карточку | новый `cards/NNN_slug.yaml` + пересборка |
| Поменять подсветку SQL или палитру по умолчанию | `static/app.js` / `--hl-*` в `static/style.css` + пересборка (`static/` копируется в образ) + `Ctrl+F5` в браузере |
| Добавить зависимость | `requirements.txt` + пересборка (слой с `pip install` кэшируется по этому файлу) |
| Сменить порт на хосте | `APP_PORT` в `.env` |
| Сменить версию Postgres | `image:` у `db`; данные не сохраняются, так что миграция не нужна |
| Перейти на gunicorn | добавить `gunicorn` в `requirements.txt` и заменить `CMD`; учти, что `init_db()` выполняется при импорте в каждом воркере, поэтому использовать один воркер или вынести инициализацию |
| Отладка с hot reload | добавить bind mount `.:/app` и `FLASK_DEBUG=1` в `app`; это dev-режим, а не дефолт |

## 6. Команды

```bash
docker compose up --build        # собрать и запустить
docker compose up -d --build     # то же в фоне
docker compose logs -f app       # логи приложения
docker compose logs -f db        # логи Postgres
docker compose down              # остановить и удалить контейнеры
docker compose exec db psql -U postgres -d sql_trainer   # зайти в БД
```

(Пользователь и имя базы в последней команде — дефолтные; подставь
свои, если они заданы в `.env`.)

## 7. Диагностика

- `app` падает с `OperationalError: could not connect to server` — не
  сработал healthcheck/ожидание, либо `DB_HOST` не `db`. Проверь
  `environment:` у `app`.
- `password authentication failed` — в `.env` изменили пароль после
  первого запуска. Volume у Postgres нет, поэтому достаточно
  `docker compose down` и `up` заново.
- Порт 5000 занят на хосте — задай `APP_PORT`.
- Изменения в коде «не видны» — образ не пересобран, нужен
  `--build`. Для статики (`app.js`, `style.css`) после пересборки ещё
  и сбросить кэш браузера (`Ctrl+F5`); признак старых файлов —
  нет подсветки SQL и кнопки «⚙ Настройки» в шапке.
- Карточки, созданные в UI, исчезли — ожидаемо, см. раздел про
  карточки.
